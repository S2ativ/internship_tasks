# Практика объектно-ориентированного программирования (ООП)

## Задание 1 (Реализация примеров из статей)

# `Abstract.py`

Реализация абстракции

* Импорт класса ABC и декоратора @abstractmethod из библиотеки abc
* Класс Book наследуется от абстрактного класса ABC, принимает атрибуты `title, author` при инициализации. Включает в себя метод `get_summary` , обязательный к переопределению во всех дочерних классах
* Класс Fiction, NonFiction, Poetry наследуется от Book, метод переопределяется под вывод описания, кроме Poetry т.к. он не переопределил метод, а значит остается абстрактным 

# `Beverage.py`

Реализация наследования, инкапсуляции, полиморфизма

* Класс Beverage является родителем для остальных классов и использует защищенные атрибуты `_name, _size, _price`
* Для получения данных используются геттеры, а для изменения цены используется сеттер `set_price` (инкапсуляция)
* Класс Soda дочерний класс, использует метод super() для наследования атрибутов, добавляет свой защищенный атрибут `_flavor`, переопределяет метод `describe` под себя (полиморфизм)
* Класс DietSoda также является дочерним классом,но уже наследуется от класса Soda, наследует те же атрибуты, но переопределяет метод `describe` под себя (полиморфизм)


# `Book.py`

Работа с атрибутами и состоянием объекта

* Класс Book: принимает атрибуты `title, author, isbn` при инициализации, также задает атрибут состояния `checked_out` со значением False по умолчанию
* Методы `check_out` и `check_in` осуществляют выдачу и приемку книг, изменяя состояние атрибута `checked_out` с предварительной проверкой

# `Confectionary.py`

Реализация наследования и полиморфизма

* Класс-родитель Confectionary принимает атрибуты `name, price` при инициализации, задает метод  `describe` для текстового описания
* Класс `Cake` и `Candy` дочерние классы,переопределяют метод `describe` (полиморфизм)
* Класс `Cookie` дочерний класс,но не переопределяет метод `describe` , таким образом этот метод наследуется от родителя 

# `Recipe.py`

Реализация наследования, абстракции, полиморфизма

* Абстрактный класс-родитель Recipe наследуется от ABC , задает пустой метод `cook` , который должен быть обязательно переопределен из-за декоратора @abstractmethod
* Классы `Entree` и `Dessert` дочерние классы,принимают список `ingredients` при инициализации, переопределяют метод `cook` (полиморфизм)
* Класс `Appetizer` дочерний класс,но не переопределяет метод  `cook` , из-за чего становится абстрактным (создавать объект Appetizer напрямую нельзя)
* Класс `PartyMix` наследуется от `Appetizer` , но реализует метод `cook` и завершает цепочку абстракции (полиморфизм)


# `Vehicle.py`

Реализация наследования

* Класс-родитель Vehicle принимает атрибуты `make, model, year, price` при инициализации, имеет метод `display_info` для вывода информации
* Класс `Car` дочерний класс, использует метод super() для наследования атрибутов от родителя, добавляет свои атрибуты `num_doors, body_style`
* Класс `Truck` дочерний класс, также использует метод super() для наследования атрибутов от родителя, добавляет свои атрибуты `bed_length, towing_capacity`


# `WashingMachine.py`

Работа с атрибутами объекта и модулем datetime

* Импорт модуля datetime для вычислений с датами
* Класс WashingMachine принимает атрибуты `brand, model, purchase_date, warranty_length` при инициализации
* Метод `remaining_warranty_time` рассчитывает дату окончания гарантии и возвращает строку с количеством оставшихся дней с помощью `datetime.date.today()` и `datetime.timedelta`


## Задание 2 (Реализация консольной мини-программы "Библиотека")

# `Library.py`

Реализация архитектуры (инкапсуляция, полиморфизм) и консольного меню

* Класс Book принимает атрибуты `title, author` при инициализации, задает защищенный атрибут состояния `_status`. Переопределяет магический метод `__str__` для вывода описания книги в зависимости от ее доступности (полиморфизм)
* Класс Reader принимает атрибут `num_ticket` при инициализации, создает пустой защищенный список `_history` для хранения взятых книг(инкапсуляция)
* Класс Library при инициализации создает пустые приватные списки `__books, __readers` (инкапсуляция), прямого доступа к которым извне нет
* В классе Library методы `give_book` и `take_book` проверяют наличие книги в базе,читатель зарегистрирован, и что книга есть в истории читателя, меняют `_status` и обновляют `_history`
* Методы `list_books` и `get_book_index` выводят список книг с номерами и возвращают книгу по номеру, который ввел пользователь
* Реализовано консольное меню через цикл `while True` : выдача и возврат по номеру книги, просмотр статуса книг, выход
